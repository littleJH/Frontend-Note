### 1 流程设计 V2

> 代码位置：src\app\common\flowChartV2\index.js

效果展示：
![alt text](https://jiahe-picbed.oss-cn-shenzhen.aliyuncs.com/typora-image/image-3.png)

流程设计 V2 是基于`AntV X6`图编辑引擎，用于一表通的流程表单和数据表单的流程设计模块。主要的功能难点如下：

#### 1.1 自动连线

新增或删除节点后，程序会自动连线，无需手动连线。

难点在于对「图」这种数据结构的处理。当插入或删除节点时，与该节点相关联的边和点都要做相应的处理。

例如，在分支中，当删除了当前分支的分支节点，那么整条分支上的所有节点和边都要一并删除，且整条分支首尾的边也需要重新确定与之相连的节点。

> 关键代码：
> src\app\common\flowChartV2\utils.js -- addNode
> src\app\common\flowChartV2\utils.js -- removeNode, removeBranch, removeSingleNode

#### 1.2 自动布局

新增或删除节点后，会自动布局，无需手动拖拽。

难点在于需要手动处理节点变化后的层级关系的变化并使用 `dagrejs` 算法自动布局，随后需要优化节点布局和边的布局。

> 关键代码：src\app\common\flowChartV2\utils.js -- layeredLayout

#### 1.3 后端联调数据处理

由于 V2 是在 V1 的基础上根据一表通的交互设计重写的，因此需要对接后端的流程数据格式。以下是关键点：

##### 获取流程

一表通创建空白流程表单时，会同时创建一个默认的流程，并与之绑定。
接口请求回默认流程后，需要对数据进行处理用于流程引擎的回显。如设置设置默认值、数据类型转换等。

> 关键代码：src\app\common\flowChartV2\utils.js -- getProcess

##### 保存流程

1. 流程校验：校验流程的合法性
   a. 审批节点后不能有超过一个抄送节点
   b. 条件分支下必须有独立的审批节点
   c. 不能存在相同规则的条件分支
   d. 必填校验
   
   > 关键代码：src\app\common\flowChartV2\utils.js -- checkProcess

2. 流程图处理：处理不需要的元素、修改边的起终点
   a. 删除仅用于设计时的辅助节点/边
   b. 将审批节点后的抄送节点存储的数据保存到审批节点上（流程 V1 的限制）
   c. 改写部分边的起终点，例如：边的起点是 "添加分支"节点，则让这条边的起点改成"添加分支"节点的父节点（“添加分支”节点仅用于设计使用，保存时需要去掉该节点和与之相连的所有边）
   
   > 关键代码：src\app\common\flowChartV2\utils.js -- processJson

3. 节点/边上存储的数据处理/转换，用于接口传参
   
   > 关键代码：src\app\common\flowChartV2\utils.js -- saveCell

#### 2.1 循环展示组件

> 代码位置： src\app\common\formGenerator\template\layout\Repeater\index.js

效果展示：
![alt text](https://jiahe-picbed.oss-cn-shenzhen.aliyuncs.com/typora-image/image-4.png)

循环展示组件用于根据数组类型的数据源对子组件进行循环（轮播）。主要功能难点如下：

##### 初始化循环数据源（动态数据源）

在表单初始化时，遍历 `formDesignConfig`，查找出 `Repeater` 组件，获取其 `dataSource` 配置项，构造出 `rpt` 对象（所有循环展示的数据源）和 `rptStateMap` （所有循环展示组件标识和数据源的映射关系），并将其存储到 `state` 中，供组件渲染使用。

若数据源是动态的（变量、数据集），则需要在数据源变更时（在 jsHeader 中通过 `setState` 改变数据源/数据集发生改变），重新构造 `rpt` 对象并更新 `state`。

由于 `rpt` 对象也是存储到 `state` 中的，因此为了避免性能问题，有以下两点需要注意：

1. 构造 `rpt` 对象时，若 `formDesignConfig` 中没有 `Repeater` 组件，则不进行 `setState` 操作，避免不必要的性能消耗。

2. 在 jsHeader 中通过 `setState` 改变数据源时，需要与 `rptStateMap` 进行匹配，数据源确实发生变化时（避免栈溢出）更新 `rpt` 对象中对应的数据源。
   
   > 关键代码：
   > src\app\common\formGenerator\common\index.js -- initRpt
   > src\app\common\formGenerator\common\index.js -- updateCustomState

##### 循环对象结构树的构造

根据循环数组的第一项生成属性层级树结构（广度优先，通过 [x0]、[x1] 等后缀区分不同层级的数组），在内部组件的变量选择弹窗中展示循环对象的结构树中供用户选择。

> 关键代码：src\app\common\formGenerator\utils\index.js -- getRepeaterConfig

##### [嵌套的循环展示](https://portal.ly-sky.com:9867/#/documents?docId=4f21153acc9a4e0087029867a4c4a25b&projectId=ffb0f7b7da8048618b32e306145d2c07&catalogId=heading-8)

若父级循环展示组件配置的数据源是“数据集”，只有在预览时才能获取到数据集的数据，因此不能仅限于表单初始化时构造 `rpt` 对象，还需要在预览时动态构造 `rpt` 对象。

解决方案：子循环展示组件的数据源使用绑定“函数”的形式，因为函数的入参就是当前“循环对象”和“循环索引”，只需将循环对象的某个属性返回，作为子循环展示组件的数据源即可。

关键点：

1. `src\app\common\formGenerator\template\layout\Repeater\index.js` 调用 `createNodes` 方法时，传入 `repeaterNestIndex` （被嵌套的循环展示的索引）。
2. 在 `extandRpt` 方法中调用 `extandRpt` 方法扩展 `rpt`，同时构造 `rptNestNameMap` （被嵌套循环展示的名称 name_repeaterIndex 与组件标识 name 的映射关系）。
3. 子级循环展示的内部组件所绑定的循环对象表达式，在 `handelVariableData` 中就可以通过 `rptNestNameMap` 和 `repeaterNestIndex` 获取到对应的循环对象，从而获取到对应的属性值。

> 关键代码：
> src\app\common\formGenerator\createNodeCommon.js -- createNodes
> src\app\common\formGenerator\common\index.js -- extandRpt, handelVariableData

#### 2.4 一表通流程表单设计器

##### 一表通样式风格

1. 操作按钮位置不同。
2. 基本属性、jsHeader、htmlHeader 放在右侧设置器内。
3. 组件属性分为“基本属性”和“高级属性”，样式更加美观。
4. 一表通和奕搭的组件配置文件分开。

##### 属性校验

设置了必填的属性，在表单设计保存时会进行校验，若有必填属性未填写，则提示用户填写。
关键步骤：

1. 扁平化 `formDesignConfig`，获取所有组件。
2. 遍历所有组件，检测其 `required` 属性，若为 `true` 则检测该组件的必填属性是否填写。
3. 若有未填写的必填属性，则提示用户填写，并定位到该组件。

> 关键代码: src\app\common\formGenerator\generator\index.js -- handleSave

```javascript
// 设置器必填校验
const Data = this.generator.state.Data
const flattenedItems = flattenAllFormItems(Data) // 扁平化所有嵌套项
for (const item of flattenedItems) {
  const widgetData = this.generator.sidebarRightRef.handleSelectWidgetData(item, {
    isGetData: true,
  })
  if (!widgetData) continue
  const { key, title, config, props } = widgetData
  const attrs = []
  config[1].map((item) => {
    if (item.type === 'layout' && item?.layout?.attr?.length) {
      attrs.push(...item.layout.attr.filter((item) => item.required))
    } else {
      item.required && attrs.push(item)
    }
  })
  for (const attr of attrs) {
    if (!props[attr.key]) {
      message.error(`“${props.componentTitle || title}”组件校验不通过，请完善组件属性设置`)
        // 定位到该组件
      const widgetDom = document.querySelector(`[ydkey="${item.key}"]`)
      widgetDom.click()
      setTimeout(() => {
        this.generator.sidebarRightRef?.validatorAttrForm()
      }, 100)
      return
    }
  }
}
```

单元格图片/浮动图片是 `univer` 0.5.1 版本新增的功能，即「富文本」功能。

> 关键代码：src\app\common\formGenerator\template\advance\UniverDataExcel\export.js -- valueConvert, addCustomBlocks

```javascript
// 内容转换
function valueConvert(...) {
    // ...
    else if (cell.p) {
        // 以下为 univer 源码对 cell.p.body.dataStream 的设计
        /**
         * univer packages\core\src\types\interfaces\i-document-data.ts
         *
         * Properties of document body
         * Contain three update types: range overlay, range mutual exclusion, and placeholder
         * \v COLUMN_BREAK
         * \f PAGE_BREAK
         * \0 DOCS_END
         * \t TAB
         *
         * Needs to be changed：
         * \r PARAGRAPH
         * \n SECTION_BREAK
         *
         * \b customBlock: Scenarios where customBlock, images, mentions, etc. do not participate in the document flow.
         *
         * Table

         * \x1B table row start
         * \x1C table cell start

         * \x1E customRange end

        if (body?.dataStream && body?.dataStream.includes("\b") && body.customBlocks?.length > 0) {
            value = addCustomBlocks(cell.p, i, j, worksheet, workbook);
        }

    }

/**
 * 添加自定义块（主要是图片）到Excel工作表中
 * @param {Object} p - 包含body、documentStyle、drawings等数据的对象
 * @param {number} i - 列索引
 * @param {number} j - 行索引
 * @param {Object} worksheet - Excel工作表对象
 * @param {Object} workbook - Excel工作簿对象
 * @returns {*} value - 返回值（当前未使用）
 */
function addCustomBlocks(p, i, j, worksheet, workbook) {
    // 解构获取必要的数据
    const { body, documentStyle, drawings } = p;
    const { customBlocks } = body;
    let value;

    // 遍历所有自定义块
    customBlocks.forEach((block) => {
        // 获取块的唯一标识
        const { blockId } = block;
        // 根据blockId从drawings中获取对应的绘图对象
        const drawing = drawings[blockId];

        if (drawing) {
            // 解构获取绘图对象的属性
            const { imageSourceType, source, transform } = drawing;
            // 获取变换属性：角度、宽度、高度、顶部位置、左侧位置
            const { angle, width, height, top, left } = transform;

            // 处理单元格图片
            if (imageSourceType === "BASE64") {
                // 将Base64图片添加到工作簿中，返回图片ID
                const imageId = workbook.addImage({
                    base64: source, // Base64编码的图片数据
                    extension: "png", // 图片格式
                });

                // 将图片添加到工作表的指定位置
                worksheet.addImage(imageId, {
                    tl: { col: i, row: j }, // 左上角位置（top-left）
                    // br: { col: i + 1, row: j + 1 }, // 右下角位置（bottom-right）- 已注释
                    ext: { width: width, height: height }, // 图片尺寸
                    editAs: "oneCell", // 编辑模式：随单元格移动和调整大小
                });
            }
        }
    });

    return value;
}
```

关键点：

```javascript
function handleCellDataType(...) {
    // ...
    switch (type) {
        case "file":
            cell.v = "";
            // 处理单元格类型额外值
            handleCellTypeExtraValue(cell, cellConfig, element, _this);
            break;
        case "image":
            cell.v = "";
            // 处理单元格类型额外值
            handleCellTypeExtraValue(cell, cellConfig, element, _this, indexs);
            break;
        // ...
    }
}
```

## 二、工作感受

### 1. 团队氛围

从原来的基础平台组，到现在的奕搭组，每位同事都很友好，乐于助人，工作氛围轻松愉快，大家相处融洽。

### 2. 工作内容

基础平台组的工作内容比较丰富，在主要支持奕搭的同时，还涉及支持其他部门的项目，例如：研发三部教务系统、研发一部一表通系统、部门内的基础平台等，工作内容比较多样化，设计的技术面比较广，也有一定的技术深度，也能接触到项目架构相关的内容。

奕搭组的工作内容相对单一，即对奕搭系统的迭代，工作内容比较专一。奕搭是一个业务性和技术性都非常强的项目，工作内容的技术面和深度都比较高，能学到很多技术和业务相关的知识。

### 3. 工作强度

工作强度适中，偶尔会有加班，但总体来说还是比较轻松的。

## 三、建议

### 1. 对部门的建议

1. 强烈建议加班时，只加班到晚上七点半。
2. 希望能够适当开一些技术分享会，提升团队的技术氛围。能够给新人接触核心技术的机会。
3. 希望团建活动能够按组进行，而不是按部门。

### 2. 对奕搭前端组负责人的建议

1. 希望能多给新人一些接触核心技术的机会。比如分配有挑战性的核心功能的开发任务、技术分享会等。
